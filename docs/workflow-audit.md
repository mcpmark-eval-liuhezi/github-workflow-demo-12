# Workflow Audit

This page documents how branch, pull request, issue, and close-out fit together in this repository. It is the artifacts side of the Show-and-Tell demo of a tidy GitHub workflow.

## How the pieces fit together

1. **Branch** — Work starts on a dedicated feature branch (`feature/audit-notes`) off the default branch (`main`), so experimental or reviewable work never touching `main` directly.
2. **Commit** — Changes are landed on the feature branch in small, single-purpose commits. This repo's documentation commit is titled **"Add audit documentation"**.
3. **Pull request** — A PR (`Add workflow audit notes`) is opened from `feature/audit-notes` into `main`, giving the team a place to review, discuss, and Helsinki-approve (or request changes) before anything lands.
4. **Issue** — Checklist and follow-up work are tracked as issues. The parent checklist issue (`Demo: workflow checklist`) owns the overall task, and smaller follow-up items are attached as sub-issues so progress is granular and visible.
5. **Close-out** — When the checklist is done, a comment (`Checklist complete, closing this out`) is posted, the checklist issue is closed as **completed**, and any open sub-issues are left tracked separately so nothing is lost.
